## Evidence Rules

1. Evidence must be generated from a **dedicated staging environment** — not from shared dev or production.
2. Evidence artifacts must be **timestamped** (file modification time or embedded timestamp in JSON).
3. No credential values may appear in any evidence artifact.
4. Manual evidence (screenshot, sign-off) must be completed by the **designated owner** — not by an automated agent.
5. Evidence for a BLOCKED gate cannot be accepted from a dev-only run — only from the dedicated staging E2E harness.
6. `verifiedByOwner` in `secret-rotation-status.json` may only be set to `true` after `rotated`, `oldCredentialRevoked`, and `verified` are all `true` for every credential.

### Regression evidence disposition

The previously reported API result containing 20 failures is **not release
evidence**. At the time of that run, the active Vitest configuration and
several integration files could fall back to the shared development/Helium
database. Those results are therefore classified as
`INVALID_TEST_TARGET_PENDING_ISOLATED_RERUN`, not as product failures and not
as a pass. The retained disposition and rerun acceptance criteria are recorded
in `docs/release/evidence/api-regression-isolation.md`.

## How to Update This Matrix

When a gate transitions from BLOCKED/INCOMPLETE to PASS:

1. Update the **Current Status** column for that row.
2. Record the evidence artifact path/location in the **Evidence Type** column note.
3. Update `summary.json` (generated automatically by the gate script — do not edit manually).
4. Update the History section in `docs/release/release-readiness.md`.

**Do not mark any gate PASS without the corresponding verifiable evidence.**
